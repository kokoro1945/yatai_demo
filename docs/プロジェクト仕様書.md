## プロジェクト概要

### プロジェクト名
屋台部ダッシュボード（試作）

### 目的
大学祭の屋台をキャンパスごとの配置図としてブラウザに表示し、
屋台ごとの状態や担当情報を一目で把握できる Web アプリの試作版を作成する。

本アプリは **GitHub Pages で公開する静的 Web アプリ** とし、
データは Supabase を利用して取得・認証する。

### スケジュール
- 開発開始：2024/01/01
- リリース予定：未定

---

## 対象ユーザー

### 大学祭実行委員会（屋台配置・確認担当）
- **いつ使うか：** 配置図の確認・調整時、大学祭準備期間中
- **どういうときに使うか：** 屋台の状態や情報を素早く確認・修正したいとき

## 機能要件

### 1. 認証・ログイン

**概要：**
Supabase Auth を使ってメールアドレスとパスワードでログインする。

**詳細仕様：**
- 未ログイン時はログイン画面のみ表示
- ログイン成功時にセッションを保持し、以降はダッシュボードを表示
- ログアウトでセッションを破棄しログイン画面へ戻る

### 2. ユーザー情報の表示

**概要：**
ログインしたユーザーの情報を `profiles` テーブルから取得して表示する。

**表示項目：**
- ユーザーID（Supabase Auth のユーザー ID）
- ロール（ADMIN / LEAD / PATROL など）
- 担当エリア（A〜L など）

### 3. 屋台マップの表示

**概要：**
キャンパスごとの屋台配置をグリッド状に表示する。

**詳細仕様：**
- キャンパス切り替え（本キャン / Eキャン）
- キャンパスごとにエリア（A〜F / G〜L）を表示
- 屋台タイルをクリックすると詳細パネルが更新される

### 4. 屋台の状態と色分け

**概要：**
`booth_status` の状態に応じて屋台タイルを色分けする。

**判定ロジック：**
- `sales_allowed = false` → 販売停止（赤）
- `warn_count >= 2` → 警告2以上（オレンジ）
- `warn_count = 1` → 警告1（黄）
- `gas_check = false` または `kenshoku = false` → 確認未完了（灰）
- 上記以外 → 正常（緑）

### 5. 屋台詳細パネル

**概要：**
選択中の屋台情報を詳細パネルに表示する。

**表示項目：**
- 屋台番号（yatai_id）
- エリア
- 団体名
- 警告数
- 検食 / ガス確認 / 販売可否

**補足：**
停止/解除の操作ボタンは次フェーズの機能として UI のみ配置。

### 6. データ取得とリアルタイム反映

**概要：**
Supabase から屋台データと状態を取得し、状態はリアルタイムで反映する。

**取得対象：**
- `booths` テーブル（屋台基本情報）
- `booth_status` テーブル（警告・確認・販売可否）
- `profiles` テーブル（ログインユーザー情報）

**リアルタイム：**
- `booth_status` の変更を `postgres_changes` で購読し、画面に反映

## 画面設計

- `booth_status` の変更がリアルタイムで反映

## データベース設計

**使用サービス:** Supabase（PostgreSQL）

### 1. profiles テーブル

**用途:** ログインユーザーのロールや担当エリアを管理  
**アプリで使用するカラム:**
| カラム名 | 内容 |
| --- | --- |
| id | Supabase Auth のユーザーID |
| role | ロール（ADMIN / LEAD / PATROL など） |
| area | 担当エリア（A〜L など） |

### 2. booths テーブル

**用途:** 屋台の基本情報を管理  
**アプリで使用するカラム:**
| カラム名 | 内容 |
| --- | --- |
| yatai_id | 屋台ID（A1〜L15 など） |
| area | 屋台の所属エリア |
| booth_no | 屋台番号 |
| booth_name | 屋台名 |
| org_name | 団体名 |
| sponsor_flag | 協賛フラグ |

### 3. booth_status テーブル

**用途:** 屋台の状態を管理  
**アプリで使用するカラム:**
| カラム名 | 内容 |
| --- | --- |
| yatai_id | 屋台ID |
| warn_count | 警告数 |
| kenshoku | 検食確認 |
| gas_check | ガス確認 |
| sales_allowed | 販売可否 |

## API 設計

**使用サービス:** Supabase（JS SDK）

### 1. 認証 API（Supabase Auth）

**使用している操作:**
- セッション取得: `auth.getSession()`
- 状態監視: `auth.onAuthStateChange(...)`
- ログイン: `auth.signInWithPassword({ email, password })`
- ログアウト: `auth.signOut()`

### 2. データ取得 API

**使用しているクエリ:**
- `profiles`: `select("id, role, area").eq("id", userId).maybeSingle()`
- `booths`: `select("yatai_id, area, booth_no, booth_name, org_name, sponsor_flag").order("booth_no")`
- `booth_status`: `select("yatai_id, warn_count, kenshoku, gas_check, sales_allowed")`

### 3. リアルタイム購読

**対象テーブル:** `booth_status`  
**購読方法:** `postgres_changes` を使用して `INSERT / UPDATE / DELETE` を反映
